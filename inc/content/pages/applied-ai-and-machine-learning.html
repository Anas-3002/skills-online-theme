WHAT YOU WILL BUILD

Four systems you can defend in an interview

Each project is reviewed by a working engineer and merged into a repository you own.

travel_explore

A retrieval service with hybrid search

Chunking, embeddings, keyword+vector fusion and re-ranking, with an evaluation harness that reports retrieval quality per query class.

tune

A fine-tuning pipeline

LoRA/QLoRA fine-tunes on an open-weight model, with dataset versioning, held-out evaluation and a documented decision on when fine-tuning beats prompting.

dns

An inference deployment

Batched, quantised serving behind a queue with autoscaling, timeouts and cost telemetry you can explain in an interview.

smart_toy

An agent that fails safely

Tool-calling agent with idempotent actions, retry budgets, prompt-injection defences and full trace logging.

CURRICULUM

Six modules, in order

Each module ends with reviewed work. Later modules assume the earlier ones are done — that is the point.

Python packaging, data loading, GPU vs CPU trade-offs, reproducibility, and how to read a model card without guessing what it does.
Chunking strategies, embedding model selection, hybrid keyword + vector search, re-ranking, and an evaluation set you build from real queries.
pgvector and HNSW parameters, index build cost, recall/latency trade-offs, and when a vector store is the wrong answer.
LoRA/QLoRA, dataset construction, leakage checks, offline metrics, and A/B evaluation against a prompted baseline.
Batching, quantisation, caching, streaming responses, budget alerts, and a p95 latency budget you can defend.
Tool design, retries and idempotency, guardrails against retrieved-content injection, and observability across multi-step runs.
Module list is the published curriculum for the current cohort. Ordering and emphasis are adjusted between cohorts as tooling and hiring practice change; the learning outcomes do not.
