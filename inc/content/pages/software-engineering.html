WHAT YOU WILL BUILD

Four systems you can defend in an interview

Each project is reviewed by a working engineer and merged into a repository you own.

api

A typed API with a real schema

Go or TypeScript service, migrations, indexes, request validation and contract tests against a Postgres schema you designed.

conveyor_belt

An event-driven workflow

A queue-based pipeline with idempotent consumers, retry and dead-letter handling, and a replay plan.

bolt

A caching layer that holds

Cache-aside with stampede protection, invalidation strategy and hit-rate telemetry.

devices

A frontend that stays fast

Server-rendered interface with streaming data, sensible bundle budgets and Core Web Vitals measured on a throttled connection.

CURRICULUM

Six modules, in order

Each module ends with reviewed work. Later modules assume the earlier ones are done — that is the point.

Git workflow, code review etiquette, testing strategy (unit, contract, integration) and the tooling that keeps a repository healthy.
Schema design, normalisation trade-offs, indexes, query plans and the migration habits that avoid downtime.
HTTP semantics, versioning, pagination, idempotency keys, error contracts and observability from the first commit.
Queues, workers, backpressure, retries and exactly-once illusions; when to reach for a broker and when a table is enough.
Redis patterns, profiling, N+1 elimination, connection pooling and the cost of the queries you wrote.
Component architecture, accessibility, performance budgets, and shipping a UI that survives real data volumes.
Module list is the published curriculum for the current cohort. Ordering and emphasis are adjusted between cohorts as tooling and hiring practice change; the learning outcomes do not.
